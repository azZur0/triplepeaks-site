# Triple Peaks — Marketing Site

Marketing site for [triplepeaks.coach](https://triplepeaks.coach).

The app itself lives at [app.triplepeaks.coach](https://app.triplepeaks.coach).

## Pages

**All pages are generated** in English and German from single templates (see [Internationalization](#internationalization-i18n)), so the two languages share one nav/footer and can't drift:

- **Home** (`index.html` / `index-de.html`) — from `templates/index.html`
- **Features** (`features.html` / `features-de.html`) — from `templates/features.html`
- **What's new** (`whats-new.html` / `whats-new-de.html`) — from `templates/whats-new.html`, rendered from `data/release-notes.{en,de}.json` (see below)
- **Support** (`support.html` / `support-de.html`) — from `templates/support.html`
- **Imprint** (`imprint.html` / `imprint-de.html`) — from `templates/imprint.html` + `partials/legal_imprint_body.{en,de}.html`
- **Terms** (`terms.html` / `terms-de.html`) — from `templates/terms.html`
- **Privacy** (`privacy.html` / `privacy-de.html`) — from `templates/privacy.html`
- **404** (`404.html`, English only) — from `templates/404.html`; GitHub Pages serves it for any unknown path

`sitemap.xml` is generated alongside the pages; `robots.txt` is static.

The app (web footer, iOS subscription screens, transactional emails) links to `/privacy`, `/terms` and `/imprint`, so those three page names must not be renamed.

Marketing copy lives in `i18n/*.json`. Legal bodies are long, rarely-changing prose, so they live as **verbatim per-language HTML partials** (`partials/legal_*_body.{en,de}.html`) rather than JSON strings — edit the relevant `.en.html` / `.de.html` file directly.

## Tech Stack

- Plain HTML/CSS/JS — no framework
- Translated pages are generated by a tiny **dependency-free Node script** (`build.mjs`, stdlib only — no `npm install`)
- [Inter](https://fonts.google.com/specimen/Inter) + [Montserrat](https://fonts.google.com/specimen/Montserrat) as **self-hosted variable fonts** (`fonts/*.woff2`, latin subset, OFL) — the site makes no third-party requests, which is what lets the privacy page say "no cookies, no trackers, nothing loaded from other domains"
- Hosted on GitHub Pages

## Internationalization (i18n)

The marketing pages are built in English and German from one source each, so structure lives once and copy can't drift between languages.

- **`templates/*.html`** — page structure, with `{{token}}` placeholders where translatable text/attributes go.
- **`templates/partials/`** — shared and per-language includes:
  - `head.html`, `nav.html`, `footer.html` — shared chrome, pulled in with `{{> head}}` / `{{> nav}}` / `{{> footer}}` (one source for every page; `head.html` carries the meta, social-share, favicon, font and stylesheet tags).
  - `legal_*_body.{en,de}.html` — per-language content blocks, pulled in with `{{>@ legal_imprint_body}}` (resolves to the `.<lang>.html` file for the language being built).
- **`i18n/en.json` / `i18n/de.json`** — flat `"key": "value"` string maps (values may contain inline HTML like `<em>`). Must have identical keys.
- **`build.mjs`** — renders each template in each language: English → `<name>.html`, German → `<name>-de.html`.

The templates, `partials/`, and `i18n/*.json` are the only files you hand-edit.

The generated `*.html` files and `sitemap.xml` are **git-ignored** and produced by the build (locally and in CI). Never edit them directly — edit the template or the JSON and rebuild.

Asset paths are root-absolute (`/css/style.css`, `/img/...`, `/fonts/...`) because the 404 page is served for arbitrary nested paths; the site lives at the domain root, so this is safe.

The build fails loudly if `en.json` and `de.json` don't cover the same keys, or if any `{{token}}` is left unresolved — so a missing translation is a build error, not a silent visual bug.

**To change home-page copy:** edit `templates/index.html` (structure) and/or the JSON files (wording), then run `node build.mjs`.

**To add a page:** drop a template into `templates/`, add its strings to both JSON files, and give it a `PAGES` entry in `build.mjs` (`de: false` builds it in English only and keeps German links pointing at the English file).

## What's new page (pulled from the app)

`data/release-notes.en.json` and `data/release-notes.de.json` are the responses of the app's public changelog API (`GET https://app.triplepeaks.coach/api/v1/changelog`, one call per `Accept-Language`), the same endpoint the mobile apps use for their What's new popup. `build.mjs` renders them into the What's new page and into the "shipped recently" strip on the home page.

`.github/workflows/fetch-release-notes.yml` refreshes them nightly and on demand: it runs `scripts/fetch-release-notes.py`, commits the JSON to `master` when something changed, and starts the deploy workflow. It needs no secrets, because the endpoint is public and the job only writes to this repository. GitHub pauses scheduled workflows in a public repository after 60 days without any activity and emails you; re-enable it from the Actions tab if that happens.

To refresh locally: `python3 scripts/fetch-release-notes.py && node build.mjs`.

## App screenshots

`img/app/framed/phone-NN.webp` (680×1442, transparent, one per app screen) are exported by the app repository's screenshot pipeline (`scripts/appstore/sync-site-phones.sh`, driven by its `/refresh-store-assets` skill) and copied straight into this repo. The slot → phone-number mapping is the `site:` field in the app's `scripts/appstore/screens.yaml`. Don't hand-capture or hand-edit them: every mapped file is overwritten on the next sync, and a file deleted here comes back unless its `site:` field is removed over there too. A mapped slot no page uses is harmless, just dead weight. To get a new screen on a page, add a slot in the app repo rather than capturing by hand.

## Local Development

Build the translated pages first, then serve:

```bash
node build.mjs && python3 -m http.server 8090
```

Open http://localhost:8090 (English) and http://localhost:8090/index-de.html (German). Re-run `node build.mjs` after editing a template or JSON file. The build is instant (no dependencies).
